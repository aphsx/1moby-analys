## 1. น้ำเสียงและกติกาการเขียน

- **ไทยเป็นหลัก** ศัพท์อังกฤษใช้ได้เฉพาะ: SMS, Email, OTP, API, AI, Account Manager, model card, SHAP (ใน ⓘ เท่านั้น)
- เขียนจากมุมผู้ใช้: "โอกาสเลิกใช้" ไม่ใช่ "churn probability", "ต้องเติมเครดิตใน 14 วัน" ไม่ใช่ "credit urgency: critical"
- ประโยคสั้น บอกตรง ไม่มีเครื่องหมายตกใจ ไม่มี emoji
- ทุกตัวเลขเปรียบเทียบต้องบอกฐานในวลีเดียวกัน: "+4.2% จากปี 2567" ไม่ใช่ "+4.2%" ลอย ๆ
- ชื่อหน้าเป็นคำนาม: "ภาพรวมลูกค้า", "รายชื่อลูกค้า", "บัญชี #10482"
- ข้อค้นพบใต้ชื่อหน้าพูดถึงข้อมูล ไม่ใช่วิธีใช้หน้าจอ (✗ "หน้านี้แสดง…" ✓ "ครึ่งหนึ่งของรายได้ที่เสี่ยงหายอยู่กับลูกค้ามูลค่าสูง 55 ราย")

ตัวอย่างแทน `apps/web/src/lib/format.ts` (ของเดิมใส่ "M ฿" ไว้ท้าย และ `toLocaleString()` ไม่ระบุ locale ทำให้ผลต่างตามเครื่อง):

```ts
const LOCALE = "th-TH";
const MINUS = "−";
const nf = (o?: Intl.NumberFormatOptions) => new Intl.NumberFormat(LOCALE, o);

export const formatCount = (n: number) => nf({ maximumFractionDigits: 0 }).format(n);

export function formatBaht(v: number): string {
  return (v < 0 ? MINUS : "") + "฿" + nf({ maximumFractionDigits: 0 }).format(Math.abs(v));
}

export function formatBahtCompact(v: number): string {
  const a = Math.abs(v), s = v < 0 ? MINUS : "";
  if (a >= 1_000_000) return `${s}฿${nf({ minimumFractionDigits: 1, maximumFractionDigits: 1 }).format(a / 1_000_000)}M`;
  if (a >= 1_000) return `${s}฿${nf({ maximumFractionDigits: 0 }).format(a / 1_000)}K`;
  return formatBaht(v);
}

export const formatPercent = (p: number, digits = 0) =>
  nf({ style: "percent", minimumFractionDigits: digits, maximumFractionDigits: digits }).format(p);

export function formatSignedPercent(p: number, digits = 1): string {
  const body = formatPercent(Math.abs(p), digits);
  return p > 0 ? `+${body}` : p < 0 ? `${MINUS}${body}` : body;
}

export function formatDaysAhead(days: number | null): string {
  if (days == null) return "—";
  return days > 90 ? "เกิน 90 วัน" : `ใน ${Math.round(days)} วัน`;
}

export function formatDaysAgo(days: number | null): string {
  if (days == null) return "—";
  if (days <= 0) return "วันนี้";
  return days === 1 ? "เมื่อวาน" : `${days} วันก่อน`;
}

// th-TH ใช้ปฏิทินพุทธอยู่แล้ว: 2026-01-01 → "1 ม.ค. 2569"
const DATE = new Intl.DateTimeFormat(LOCALE, { day: "numeric", month: "short", year: "numeric", timeZone: "Asia/Bangkok" });
export const formatDate = (iso: string) => DATE.format(new Date(iso));

// "2025-01" → "ม.ค." หรือ "ม.ค. 68" เมื่อ withYear
export function formatMonth(ym: string, withYear = false): string {
  const [y, m] = ym.split("-").map(Number);
  return new Intl.DateTimeFormat(LOCALE, { month: "short", ...(withYear ? { year: "2-digit" } : {}), timeZone: "UTC" })
    .format(new Date(Date.UTC(y, m - 1, 1)));
}
```

เขียน unit test ให้ทุกฟังก์ชัน (`apps/web/src/lib/format.test.ts` วางข้างไฟล์ตามธรรมเนียมของ repo) โดยเฉพาะค่าลบ, ศูนย์, null และขอบ 1,000 / 1,000,000

## 5. ข้อความใน ⓘ

ใช้ตามนี้ ตัวเลขในวงเล็บปีกกามาจากข้อมูลจริงตอน render

| ที่ | ข้อความ |
|---|---|
| KPI รายได้ที่เสี่ยงหาย | ผลรวมของ โอกาสเลิกใช้ × มูลค่าที่คาดว่าจะจ่ายใน 6 เดือน ของลูกค้า {scored} รายที่มีคะแนน อีก {unscored} รายใช้งานไม่ถึง 90 วัน ยังไม่มีคะแนน |
| KPI รายได้ 12 เดือนล่าสุด | ยอดเติมเครดิตรวม 12 เดือนก่อนวันตัดข้อมูล จากตารางการชำระเงิน เทียบกับ 12 เดือนก่อนหน้านั้น |
| KPI ต้องเติมเครดิตใน 14 วัน | วันที่คาดว่าลูกค้าจะเติมเครดิตครั้งถัดไป ทำนายจากรอบการเติมเงินที่ผ่านมา นับจากวันตัดข้อมูล {cutoff} |
| KPI การใช้งานลดลง | เทียบจำนวนข้อความ 90 วันล่าสุดกับ 90 วันก่อนหน้า นับลูกค้าที่ใช้งานลดลงหรือไม่ได้ใช้เลย |
| แผนที่ / กราฟ value × risk | แถวคือกลุ่มมูลค่า (จากมูลค่า 6 เดือนของรอบนี้) คอลัมน์คือระดับโอกาสเลิกใช้ตามเกณฑ์ใน model card ({medium}, {high}, {critical}) ขนาดคือรายได้ที่เสี่ยงหาย |
| สะพานมูลค่า 6 เดือน | แท่งแรกคือมูลค่าที่คาดว่าลูกค้า {scored} รายจะจ่ายใน 6 เดือน แท่งสีคือส่วนที่อาจหายตามโอกาสเลิกใช้ของแต่ละกลุ่ม แท่งสุดท้ายคือที่เหลือถ้าไม่มีใครติดต่อลูกค้าเลย |
| Unit chart | หนึ่งช่องคือรายได้ ฿100K ที่อาจหายไปใน 6 เดือน สีของช่องคือระดับความเสี่ยง |
| รายได้รายเดือน | ยอดเติมเครดิตรวมต่อเดือน เส้นสีคือปีนี้ เส้นเทาคือปีก่อน เป็นข้อมูลจริง ไม่ใช่ผลทำนาย |
| ต้องโทรก่อน | ลูกค้ามูลค่าสูงที่โอกาสเลิกใช้ระดับสูงหรือวิกฤต เรียงตามรายได้ที่เสี่ยงหาย |
| โอกาสเลิกใช้ (หน้าลูกค้า) | โอกาสที่ลูกค้าจะเลิกใช้ ปรับเทียบ (calibration) แล้ว อ่านเป็นเปอร์เซ็นต์ได้ตรง ๆ: 78% คือจากลูกค้าลักษณะนี้ 100 ราย คาดว่าจะเลิกใช้ราว 78 ราย |
| ปัจจัยที่มีผล | ผลของแต่ละปัจจัยต่อคะแนนของลูกค้ารายนี้ (SHAP) แถบไปทางขวาทำให้เสี่ยงขึ้น ไปทางซ้ายช่วยลดความเสี่ยง ความยาวเทียบกันได้เฉพาะในลูกค้ารายนี้ |
| มูลค่า 6 เดือน | ยอดที่คาดว่าจะชำระใน 6 เดือนข้างหน้า คิดจากความถี่และยอดเติมเงินที่ผ่านมา ช่วงคาดการณ์คือค่าต่ำสุด–สูงสุดที่น่าจะเป็น |
| เติมเครดิตครั้งถัดไป | จำนวนวันที่คาดว่าลูกค้าจะเติมเครดิตครั้งถัดไป นับจากวันตัดข้อมูล ช่วงคาดการณ์บอกว่าอาจเร็วหรือช้าได้แค่ไหน |
| โอกาสยังใช้งานอยู่ | ความน่าจะเป็นที่ลูกค้ายังเป็นลูกค้าอยู่ ดูจากความถี่และระยะห่างของการซื้อที่ผ่านมา |
